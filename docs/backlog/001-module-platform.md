# 001 — Модульный каркас: реестр, роли, доступ

## Цель

Ядро платформы v2: реестр модулей с дескрипторами (секции, права, бизнес-роли,
колонки, MCP-инструменты), AccessService с проверкой «пересечения»,
предоставление и включение модулей в два шага, спящие роли.

## Контекст

Спека §2, §5. Сейчас в v1 роли плоские (админ инстанса / владелец проекта /
developer / tester), модулей нет, qa-функциональность в ядре.

## Критерии готовности

- Дескриптор модуля в коде описывает секции, права, роли, колонки и
  инструменты; реестр собирает дескрипторы статически.
- AccessService — единственная точка проверки; контроллеры, Livewire и Blade
  спрашивают `module.section.verb`.
- Предоставление (админ инстанса) и включение (владелец проекта) — раздельные
  шаги с UI у обоих.
- Доступ = членство ∧ предоставлен ∧ включён ∧ право; без права — заглушка,
  без включения — модуль скрыт из UI и API.
- Роль непредоставленного модуля спит и оживает при возврате; назначение
  спящей роли невозможно (фильтр ролей).
- Удаление модуля или роли релизом гасит их строки в БД; неизвестная роль
  отображается слагом, не 500.
- qa-модуль: существующие роли, маршруты и инструменты v1 выражены через
  дескриптор, поведение v1 не меняется.
