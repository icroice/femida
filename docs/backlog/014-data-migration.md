# 014 — Миграция данных v1 → v2

## Цель

Существующие инстансы v1 обновляются до v2 без потери данных: пользователи,
проекты, кейсы, сессии, скриншоты остаются; появляется модульная база.

## Контекст

Спека §4, §5. Выполняется после 011 (весь v1 — модуль `qa`).

## Критерии готовности

- Миграция: каждому существующему проекту — предоставление и включение
  всех модулей стартового набора.
- Роли участников v1 назначаются бизнес-ролями модуля `qa`
  (developer → `qa.developer`, tester → `qa.tester`, владелец остаётся
  владельцем).
- Задач в v1 нет — доска стартует пустой, пул открывается модулем `backlog`.
- Обновление отрабатывает на копии прод-данных инстанса владельца без
  ошибок и с проверкой целостности (счётчики записей до/после).
- Откат не предусматривается: перед обновлением — бэкап (документировать
  в deploy-инструкции).

## Нерешённые вопросы

- Проводить ли миграцию автоматически при `artisan migrate` или отдельной
  командой с подтверждением.
