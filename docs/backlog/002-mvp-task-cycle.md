# 002 — MVP-цикл задачи

## Цель

Ручной конвейер задачи от создания до «готово»: доска, страница задачи,
бэклог-таблица, страница сделанного — по `docs/TZ.ru.md` (разделы 5–7;
решения v2-20, v2-21).

## Контекст

До этого: 024 (аудит), 023 (URL на ключе). Опора: движок 001, сущность
задачи и история переходов 005, каркас 006.

## Критерии готовности

- Реестр модулей: конвейер из ТЗ §5 — `backlog` «новые», `spec`
  «проработка спеки» + «готово к разработке», `dev` «разработка»,
  `review` «ревью», `qa` «тестирование», `release` «готово к релизу» +
  «готово»; драфт-колонки `qa` (intake/verify/done) убраны.
- Доска `/{KEY}/board`: шесть средних колонк из реестра, порядок по
  жизненному циклу; карточка — код (проект грузить `with('project:id,key')`,
  нота ревью 005), название, ответственный; счётчик в заголовке колонки;
  клик по карточке — страница задачи.
- Страница задачи `/{KEY}/{n}`: название, описание (markdown),
  ответственный (селект участников), бейдж статуса; кнопки
  «→ {следующий статус}» / «← {предыдущий}» через TaskService — только
  соседние переходы, на краях конвейера скрыты; внизу — история
  переходов (кто, когда, откуда → куда).
- `/backlog`: таблица задач со статусом «новые» (номер по возрастанию,
  название, ответственный), кнопка «Новая задача» — единственная точка
  создания: название обязательно, описание и ответственный опциональны.
- `/done`: таблица задач со статусом «готово», номер по убыванию,
  пагинация.
- Переходы пишут immutable-историю (005); повторный переход в текущий
  статус — no-op без записи.
- Доступ — только через AccessService; пустые состояния (доска, бэклог,
  done) по стайлгайду; новые паттерны (колонка, бейдж статуса) —
  сначала на витрине `/styleguide`.
