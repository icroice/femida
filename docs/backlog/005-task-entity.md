# 005 — Задача как сущность ядра

## Цель

Модель задачи — то, что движется по доске: миграции, модели, нумерация,
история переходов. Без UI (каркас 006, доска 002).

## Контекст

Спека §1, §6. Задача принадлежит проекту, живёт в колонке модуля-стадии.

## Критерии готовности

- Таблица `tasks`: проект, сквозной номер в пределах проекта (`FEM-128`),
  заголовок, описание, исполнитель, колонка (ссылка на колонку модуля).
- Номер выдаётся атомарно, без дыр при гонке (счётчик на проект).
- `task_transitions`: кто, когда, откуда, куда — каждое перемещение
  фиксируется событием с историей.
- Модели, связи, фабрики, тесты нумерации и истории.

## Нерешённые вопросы

- Префикс номера: фиксированный `FEM` или настраивается на проект.
- Состав полей карточки beyond заголовок/описание/исполнитель (лейблы?).
