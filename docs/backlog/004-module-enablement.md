# 004 — Включение модулей и их жизненный цикл

## Цель

Два шага включения модуля, UI обоих шагов, жизненный цикл модуля при
удалении.

## Контекст

Спека §5, решения v2-8/v2-17. Движок и таблица `module_states` — 001
(движок читает, эта задача пишет). Карточки-тумблеры и lock-бейджи —
паттерны стайлгайда.

## Критерии готовности

- Админ инстанса предоставляет модули проектам (UI: реестр модулей ×
  проекты).
- Админ проекта включает предоставленные модули (UI: карточки с
  тумблером; непредоставленные — приглушены lock-бейджем, не спрятаны).
- Отзыв предоставления или выключение модуля скрывает его UI/API у
  проекта (для `qa` — проверка тестом).
- Релиз, убирающий модуль, несёт миграцию, гасящую его строки
  `module_states`; неизвестный модуль отображается слагом, не 500.

## Нерешённые вопросы

- Журнал предоставлений/включений (кто и когда) — нужен ли.

## Смежные задачи

Спящие бизнес-роли и фильтр назначаемых ролей — отложенное расширение
(v2-14/v2-17), отдельной задачей, когда модульные роли появятся.
