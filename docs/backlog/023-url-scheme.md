# 023 — URL-схема на ключе проекта

## Цель

Неймспейс проекта в корне URL по ключу; slug упразднён (v2-20,
ТЗ §3).

## Контекст

Сейчас: маршруты `/projects/{project:slug}/...`, список проектов — `/`.
v2 не выпущена, внешних закладок нет — редиректы со старых путей не нужны.

## Критерии готовности

- Миграция: ключ NOT NULL и уникален (backfill из 005 уже есть),
  колонка `slug` и поле формы удалены; создание проекта — название +
  ключ (2–10 заглавных букв, уникален, не меняется).
- Маршруты проекта с констрейнтом `[A-Z]{2,10}`: `/{key}/board`,
  `/{key}/backlog`, `/{key}/done`, `/{key}/{n}` — задача; v1-страницы
  переезжают: `/{key}/cases...`, `/{key}/sessions...`, `/{key}/settings...`,
  `/{key}/screenshots/...`.
- `/` — список проектов: системный админ видит все + создание,
  разработчик — только свои; гость — на /login.
- Набранный в нижнем регистре ключ (`/tst/...`) резолвится
  регистронезависимо и получает 301 на канонический вид.
- Тесты: маршруты по ключу, 301-канон, чужой проект — 404,
  права доступа прежние.
