# 011 — Модуль `qa` — перенос функциональности v1

## Цель

Весь v1 становится модулем: библиотека кейсов, сессии прогонов, пары
скриншотов, вердикты, REST API v1 и MCP.

## Контекст

Спека §4, решения v2-7. Движок 001 уже выражает роли v1 дескриптором `qa`;
здесь переезжает сам код. Доска (002) уже живая — у модуля своя колонка
«QA» и переход в `release`.

## Критерии готовности

- Код v1 (кейсы, сессии, скриншоты, вердикты, сводки) перенесён из ядра
  в структуру модуля `qa`; маршруты и навигация — через дескриптор.
- REST API v1 и MCP-сервер работают без изменения контрактов (существующие
  клиенты не замечают переезда).
- Тесты v1 зелёные без правок ожиданий (кроме путей классов).
- В задаче появляется блок QA: линк на сессию прогона, вердикт виден на
  карточке.
- Отключение модуля `qa` у проекта скрывает его UI и API (проверка тестом).

## Нерешённые вопросы

- Структура каталогов модуля (app/Modules/Qa против привычных путей).
