# 011 — Привязка v1 к модулю `qa`

## Цель

Страницы, маршруты и доступы всего v1 (кейсы, сессии, скриншоты, вердикты,
REST, MCP) проходят через модуль `qa` — без перемещения кода. UI v1
появляется/исчезает вместе с модулем.

## Контекст

Спека §4, решения v2-7. Дескриптор `qa` и роли v1 — уже в 001. Физический
перенос кода в структуру модуля — задача 016, следующим шагом.

## Критерии готовности

- Маршруты и навигация v1 доступны только когда модуль `qa` предоставлен,
  включён и у роли есть право (AccessService).
- Поведение и контракты v1 не меняются (существующие клиенты работают).
- Отключение модуля `qa` у проекта скрывает его UI и API (проверка тестом).
- Колонка «QA» на доске: переход из `review`, блок QA в задаче (линк на
  сессию прогона, вердикт на карточке).

## Нерешённые вопросы

- Что видит участник без права `view` на модуль: пустой раздел или 404.
