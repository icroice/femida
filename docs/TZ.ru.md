# Femida — ТЗ (MVP)

> Статус: черновик 1 (2026-11-25). Основа — абстрактное ТЗ владельца от
> 2026-11-25, развёрнутое здесь до решений. Этапные докрутки (требования
> в `spec`, поля веток/PR в `dev`, прогоны в `qa`, релизные срезы в
> `release`, приоритизация в `backlog`) — отдельные ТЗ владельца по
> каждому модулю и сюда не входят. Журнал решений — SPEC.ru.md (v2-N).

## 1. Концепция

Таск-трекер типа JIRA, open-source, для установки на свой сервер и
работы над проектами. MVP — ручной конвейер задачи: создали в бэклоге,
провели по колонкам, закрыли. Автоматизация — после MVP.

## 2. Роли

- **Системный админ** (создаётся setup-мастером при первом заходе):
  видит все проекты, создаёт проекты, управляет пользователями.
  Системные ссылки (пользователи, создание проектов) видит только он.
- **Разработчик** (роль проекта, v2-17): видит только свои проекты,
  внутри проекта делает всё: доска, задачи, переходы.
- Роль администратора проекта (`admin`) — как разработчик плюс
  настройки проекта и команда (v2-17). В MVP отдельной админ-функции
  на доске нет.
- Сотрудника без роли не существует; доступ = членство ∧ право (v2-18).

## 3. Навигация и URL (v2-20)

| URL | Что | Кто |
|---|---|---|
| `/` | список проектов: у админа все + создание, у разработчика свои | после login |
| `/{KEY}` | редирект на `/board` | участники |
| `/{KEY}/board` | канбан-доска (6 колонок) | участники |
| `/{KEY}/{n}` | страница задачи (n — номер в проекте) | участники |
| `/{KEY}/backlog` | таблица задач «новые» + создание задач | участники |
| `/{KEY}/done` | таблица задач «готово», пагинация, номер по убыванию | участники |
| `/{KEY}/cases`, `/{KEY}/sessions`, `/{KEY}/settings`, `/{KEY}/screenshots/...` | v1-функциональность модуля `qa` и настройки проекта | участники |
| `/users` | пользователи: список, создание, удаление | системный админ |
| `/profile`, `/profile/keys` | профиль, пароль, личные ключи | все |

- **Ключ проекта — единственный идентификатор** (v2-20): 2–10 заглавных
  букв, уникален, не меняется. Slug упразднён.
- Ключ в URL — канонический вид; набранный в нижнем регистре (`/tst/...`)
  резолвится регистронезависимо и получает 301 на канон.
- Констрейнт маршрута `[A-Z]{2,10}` не пересекается с существующими
  корнями (они все в нижнем регистре).
- v2 не выпущена — редиректов со старых путей `/projects/{slug}/...` не делаем.

## 4. Сущности

### Проект
Название, ключ, описание (опционально). Создаёт только системный админ
(v2-11). Команда: участники с ролями admin/developer.

### Пользователь
Имя, email, пароль; флаг системного админа. Управление — на `/users`.

### Задача
- Номер `{KEY}-{n}`: n — атомарный счётчик проекта, без дыр; в URL —
  `/{KEY}/{n}`, на экране — код `TST-123`.
- Поля: название (обязательно), описание (markdown, как сводки v1),
  ответственный (участник проекта, опционально), статус (раздел 5).
- Создание — только на `/backlog`, статус всегда «новые» (v2-21).
- История: каждое создание/перемещение — immutable-переход
  (кто, когда, откуда, куда) — уже пишет TaskService (005).
- Удаление задач в MVP нет: закрытие = статус «готово».

### Ключи API
Личный ключ участника, выпускается в профиле, действует от его прав,
живёт, пока он в проекте (без изменений из v1).

## 5. Статусный конвейер (v2-21)

Порядок (позиции 1 и 8 живут на своих страницах, не на доске):

| # | Статус | Модуль | Отображение |
|---|---|---|---|
| 1 | Новые | `backlog` | `/backlog` |
| 2 | Проработка спеки | `spec` | доска |
| 3 | Готово к разработке | `spec` | доска |
| 4 | Разработка | `dev` | доска |
| 5 | Ревью | `review` | доска |
| 6 | Тестирование | `qa` | доска |
| 7 | Готово к релизу | `release` | доска |
| 8 | Готово | `release` | `/done` |

Правила:

- Переход — только на соседний статус: «вперёд» или «назад» (v2-21).
  Перепрыгивать нельзя, прямого выбора статуса нет, панель быстрых
  действий фиксированная (не настраивается).
- На краях конвейера кнопки недоступны: у «новые» нет «назад», у
  «готово» нет «вперёд».
- Drag-and-drop — вне MVP (014, отложена).
- Переходы идут через TaskService — одна дорожка, история не расходится.

## 6. Модули и колонки

Модуль декларирует свои колонки конвейера в дескрипторе (реестр 001).
**На старте функционал каждого модуля — только его колонки** (v2-21):
этапные функции приходят позже отдельными ТЗ. Колонки крайних стадий
(`backlog`, `release`) на доске не показываются — у них табличные
страницы `/backlog` и `/done`.

Существующий драфт-реестр `qa` (intake/verify/done) заменяется
колонкой «Тестирование»; v1-страницы модуля остаются как есть до 011.

## 7. Страницы

### `/` — проекты
Карточки/список. Админ: все проекты + кнопка «Создать проект» (название,
ключ). Разработчик: только свои. Гостя ведёт на /login.

### `/{KEY}/board` — доска
Шесть колонок из реестра, горизонтальный скролл при нехватке места.
Карточка: код, название, ответственный. Счётчик задач в заголовке
колонки. Карточки не создаются и не перетаскиваются (MVP): клик —
открыть задачу, переходы — на странице задачи. Пустые состояния —
по стайлгайду.

### `/{KEY}/{n}` — задача
Шапка: код + название, статус (бейдж), ответственный (селект участников).
Тело: описание (markdown). Кнопки перехода «→ {следующий статус}» и
«← {предыдущий}» — с именем целевого статуса. Внизу — история переходов
(кто, когда, откуда → куда). Комментарии — не MVP (019).

### `/{KEY}/backlog` — бэклог
Таблица задач со статусом «новые»: номер (по возрастанию), название,
ответственный. Кнопка «Новая задача» — единственная точка создания:
название обязательно, описание и ответственный опционально. Строка —
ссылка на задачу.

### `/{KEY}/done` — сделанное
Таблица задач со статусом «готово»: номер по убыванию, пагинация.

### `/users` — пользователи
Список, создание (имя, email, пароль, флаг админа), удаление.
Правила удаления — открытый вопрос №3.

### `/profile`, `/profile/keys`
Как в v1: профиль, смена пароля, личные ключи.

## 8. Права

Всё через AccessService (v2-18): доступ = членство ∧ право. Доска,
задачи, бэклог, done, переходы, создание задач — любой участник
проекта. Создание проектов, `/users` — системный админ. Настройки
проекта — admin проекта. REST/MCP — по личному ключу, от прав владельца.

## 9. Дизайн

Не в фокусе: следовать стайлгайду `/styleguide` и токенам `--fm-*`
(спека §9). Новые паттерны (колонки доски, бейдж статуса) сначала
показать на витрине.

## 10. Открытые вопросы

1. Кнопка «вперёд» в строке `/backlog` (та же дорожка TaskService) —
   удобна, но добавляет вторую точку перехода. Рекомендация: позже.
2. Редактирование полей задачи (название/описание/ответственный) —
   любой участник? Рекомендация: да, любой участник, без ограничений.
3. Удаление пользователя с активностью (задачи в исполнителях, ключи):
   запрет с причиной или отвязка? Рекомендация: запрет, пока есть
   ссылки; сообщение со списком.
4. Мобильная доска: достаточно горизонтального скролла? (014 вернётся)
5. Сортировка `/backlog`: по номеру возрастанию (приоритеты придут с
   этапным ТЗ `backlog`). Рекомендация: да.
